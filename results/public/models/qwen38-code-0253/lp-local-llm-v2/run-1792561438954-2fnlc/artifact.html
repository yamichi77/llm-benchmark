Run it on your own machine

モデルを動かす場所を、 自分のPCという 選択肢にふやす。

ローカルLLMは、サーバーに預けなくても手元の計算機で動く言語モデルです。試す速さ、モデルを選べる自由、データの扱いを自分で設計できる余白があります。特定製品の話ではなく、動かし方の話として。

01 / WHY LOCAL

サーバー前提を、ひとつ外すと見えるもの

手元で動かせると、試す回数の重さが変わります。待つ・預けるが減るぶん、気軽に触って削ってを繰り返せます。

手元で試す楽しさ

思いついた入力、言い回しの微調整、昨日の失敗のやり直し。起動しておけば、思い立ってから結果を見るまでの距離が短くなります。

何度やり直しても気にならない環境

用途に合わせて選べる

軽くして速さ寄り、重くして品質寄り、長い文脈を狙うなど、モデルと設定の組み合わせを替えられます。固定の1択に縛られません。

サイズ・量子化・設定が選択肢として残る

データの扱いを設計できる

何を入力し、どこに置き、誰と共有するか。自分たちの運用に合わせて決めやすくなります。判断の材料を自分で持てるのが利点です。

運用ルールを後から説明しやすい

02 / HOW IT RUNS

入力から応答まで、端末の中で起きること

仕組みは単純な流れの繰り返しです。外に出る工程を自分で把握できるのが、ローカル実行の性質です。

  1. STAGE 01

    入力を受け取る

    依頼文と、必要なら手元の資料やコードの抜粋を渡します。

  3. STAGE 02

    ばらして考える

    入力を書片の小さな単位に分解し、モデル内の演算を順に通します。

  5. STAGE 03

    手元で計算

    CPUやGPUが積まれたモデルの重みに沿って、次の書片を決めていきます。

  7. STAGE 04

    応答を返す

    出てきた文章を自分の環境で確認し、必要なら貼り直して続けます。

ただし「ローカルだけ」が条件ではありません。検索・API連携・同期などの機能をつけると、その分工夫はしますが通信が発生します。どの工程を外に出すかを設定で決める、という考え方になります。

03 / CHOOSE

「何をしたいか」から逆算してえらぶ

性能の言い比べより、用途に合う形を選ぶほうが近道です。タブで想定を変えてお試しください。

自分の書き出しを、置いて戻される相手として使う

一から書かせると迷う場面も、元の文を渡せば直線の相談になります。短い文を何度も行き来する使い方なら、軽く動きやすい構成から始めると続きやすいです。

入り口の練習
書けた段落を1つ貼り、「トーン違いの案を3つ」と頼む。
向けやすい形
軽量〜中程度・応答が早い構成。長い指示より短い指示を繰り返す。
やめどきの目安
直したい箇所が毎回同じなら、モデルより指示文を直したほうが早い。

エラー文と断片を貼って、見当 together に相談する

ファイル全体を渡すより、疑わしい範囲とエラーの全文を渡すほうが展開が速くなります。文脈を長く持つほど端末の負担は増えるので、載せる範囲を絞る工夫が効きます。

入り口の練習
tracebackの全文＋該当数行を貼り、原因の候補を出してもらう。
向けやすい形
ある程度まとまった文脈を扱える構成。ログは要点だけ抜く。
やめどきの目安
動作確認は自分でする前提で、案の出し手に留めると事故が減る。

手元の資料を、分類と要約の作業台に載せる

ローカルに置いた資料を貼り付けて、見出しごとに分ける・論点だけ抜き出す、という使い方です。外部機能をつなげない構成なら、入力の内容はこの端末の中に留まります。

入り口の練習
1本の資料を貼り、「ラベル3種類で分類して」と頼む。
向けやすい形
長め入力を扱える構成。分類基準を先に指定すると再現しやすい。
やめどきの目安
検索や連携を入れるときは、通信の有無を先に設定で確認する。

TYPE A

軽量・手軽さ寄り

  • 短い入力の往復に向く
  • 古い端末でも狙いやすい
  • 長い文脈や凝った指定は苦手になりやすい

TYPE B

バランス寄り

  • 用途を絞った実用に合わせやすい
  • 差し替えの比較基準にしやすい
  • 設定を詰めると急に重くなる余地あり

TYPE C

品質・長文脈寄り

  • 長い資料や凝った指示に強い狙い
  • メモリと計算の余裕が前提
  • 応答まで待つ前提の運用になる

搭載メモリから見る、はじめ方

あくまではじめ方の目安です。実際の必要量と体感は、モデル・量子化・設定・機器で動きます。

小さめ・量子化されたモデルから試すのが近道です。長文脈や重い設定は苦手にしやすいので、用途を1つに絞って1つずつ確かめる形になります。

04 / STEPS

導入は、4つの順番で考える

機器から決めると用途が歪みます。用件のほうを先に決めるのが、遠回りの少ない流れです。

  1. STEP 01

    用途を決める

    「下書きの手伝い」「コードの相談」「手元資料の整理」のどれを主にするか、一文で書いておきます。ここが曖昧だと、之后的な選択が全部ブレます。

    • 任せたいことを一文で
    • 1日何回使う想定か
    • 失敗しても困らない範囲から

  2. STEP 02

    機器と必要メモリを確認する

    搭載メモリ、グラフィックスの有無、使えるディスク容量を数えます。ここが次のモデル選びの上限になるので、推測で進めません。

    • メモリ搭載量
    • GPUの有無とVRAM
    • モデル分の空き容量

  3. STEP 03

    利用条件を読んでモデルを選ぶ

    モデルには使い方・再配布・商用利用の条件が添えられていることがあります。全モデルが無料で商用利用できるとは限らないため、公開されている条件文と説明を確認してから選びます。

    • 条件文を読む
    • 対応言語や入力長を見る
    • 必要なら複数候補を持つ

  4. STEP 04

    小さく試す

    短い入力で1往復。待つ時間が耐えられるか、出る文章が実用になるかを見て、必要ならモデルか設定だけを差し替えます。変えるものは一度に1つにすると原因が残ります。

    • 短い入力で1往復
    • 変えるのは一度に1つ
    • 失敗例もメモしておく

ページ内のCTAはこの手順までを結ぶリンクで、入力内容や個人情報をどこかへ送る仕組みはありません。

05 / CAUTION

かっこよさの裏に、決めておくこと

このページでは未測定の数値や順位は置いていません。代わりに、始める前に効いてくる注意を残します。

速さとメモリは依存する

体感の速さも必要な容量も、モデル・機器・設定で変わります。人の環境をそのまま自分の想定に持ち込まないほうが安全です。

無料・商用利用とは限らない

手元で動くことと、使い方の条件は別の話です。モデルごとに公開された条件を確認し、業務利用なら記録を残しておきます。

秘密保持は自動ではない

外部連携や設定の選び方次第で通信は起きます。完全な内側で完結させるには、どこで通信するかを自分で点検する必要があります。

成功と精度も条件付き

うまくいくかも、出た文章が使えるかも、用途とモデルに依存します。小さく試して自分で確かめる順番を大事にしてください。

まずは、用途を一文書いてみる。

場所の選択肢が増えると、試す回数が増えます。回数が増えると、自分の使い方が決まります。
